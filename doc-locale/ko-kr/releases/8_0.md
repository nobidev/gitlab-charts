GitLab의 `17.0` 릴리스를 통해 GitLab Helm chart의 `8.0` 버전을 출시했습니다.

## 주요 변경 사항 요약 {#summary-of-major-changes}

- 기존 러너 등록 워크플로우는 이제 기본적으로 비활성화되어 있습니다. [새로운 등록 워크플로우로 마이그레이션하려면 수동 작업이 필요합니다.](#runner-workflow-changes)
- PostgreSQL 13에 대한 지원이 제거되었습니다. 업그레이드하기 전에 PostgreSQL 14 이상을 실행 중인지 확인하세요.

모든 업그레이드 관련 변경 사항은 [GitLab 17 업그레이드 참고 사항](https://docs.gitlab.com/update/versions/gitlab_17_changes/)을 참조하세요.

## 7.x에서 업그레이드 경로 {#upgrade-path-from-7x}

chart의 `8.0` 버전으로 업그레이드하려면 먼저 chart의 최신 `7.11.x` 릴리스로 업그레이드해야 합니다. 최신 패치는 [버전 매핑 세부 정보](../installation/version_mappings.md)를 확인하세요.

### 8.8.0으로 업그레이드 {#upgrade-to-880}

[`shared-secrets` 작업](../charts/shared-secrets.md#disable-functionality)을 비활성화한 경우 수동으로 3개의 새로운 시크릿을 만들어야 합니다. 활성화된 경우(기본 동작) 새로운 시크릿이 자동으로 생성되므로 수행할 작업이 없습니다.

- `active_record_encryption_primary_key`
- `active_record_encryption_deterministic_key`
- `active_record_encryption_key_derivation_salt`

시크릿 형식은 [GitLab Rails 시크릿 섹션](../installation/secrets.md#gitlab-rails-secret)에서 확인할 수 있습니다.

이 3개의 시크릿을 채우는 단계는 다음과 같습니다:

1. [시크릿 백업](../backup-restore/backup.md#back-up-the-secrets)
1. `LC_ALL=C < /dev/urandom tr -dc 'a-zA-Z0-9' | head -c 32`을(를) 사용하여 3개의 서로 다른 32자 무작위 문자열 생성 - 각각의 새로운 시크릿에 대해 하나씩
1. `gitlab-secrets.yaml`의 끝에 시크릿을 추가합니다. 시크릿이 `production` 키 아래에 들여쓰기되어 있는지 확인합니다:

   ```yaml
   production:
     active_record_encryption_primary_key:
       - "<first 32-chars random string>"
     active_record_encryption_deterministic_key:
       - "<second 32-chars random string>"
     active_record_encryption_key_derivation_salt: "<third 32-chars random string>"
   ```

1. 새로운 `secret` 리소스 생성 (`<name>`을(를) 릴리스의 이름으로 바꿉니다):

   ```shell
   kubectl create secret generic <name>-rails-secret-v2 --from-file=gitlab-secrets.yaml
   ```

1. `global.railsSecrets.secret`을(를) `values.yaml` 파일에서 업데이트하여 새로운 `<name>-rails-secret-v2` 시크릿 리소스를 가리키도록 합니다.
1. 이 새로운 값으로 GitLab chart 릴리스를 업그레이드하되, 다른 기존 값이 여전히 적용되는지 확인합니다 (예를 들어 [`--reuse-values` 플래그를 사용하지 마세요](../installation/upgrade.md)).
1. GitLab이 예상대로 작동하는지 확인합니다. 그렇다면 기존 `<name>-rails-secret` 시크릿 리소스를 삭제해도 안전합니다.

### 8.6.0으로 업그레이드 {#upgrade-to-860}

레지스트리 메타데이터 데이터베이스에 대한 데이터베이스 마이그레이션을 수행하는 작업의 `app` 레이블이 `registry`에서 `registry-migrations`으로 변경되었으므로 컨테이너 레지스트리 `Deployment` 및 `PodDisruptionBudget`의 선택기 문제를 해결합니다.

레지스트리 메타데이터 데이터베이스가 활성화되지 않았거나 모니터링 또는 로깅 솔루션과 같은 외부 도구에서 사용하지 않는 경우 수행할 작업이 없습니다. 이 레이블을 사용하는 경우 그에 따라 업데이트하세요.

### 8.6.x, 8.5.1, 8.4.3, 8.3.6으로 업그레이드 {#upgrade-to-86x-851-843-836}

이 변경 사항은 [GitLab NGINX chart](../charts/nginx/_index.md)를 사용 중이고 자신의 NGINX RBAC 규칙을 설정한 경우에만 영향을 미칩니다.

자신의 [외부 NGINX chart](../advanced/external-ingress/_index.md)를 사용 중이거나 NGINX RBAC 규칙 변경 없이 GitLab NGINX chart를 사용 중인 경우 이 섹션을 건너뛸 수 있습니다.

Helm chart 버전 8.6.0, 8.5.1, 8.4.3, 8.3.6에서는 Ingress NGINX Controller 이미지가 v1.11.2로 업데이트되었지만 Ingress NGINX Controller chart 버전은 여전히 4.0.6입니다. 이전 `v1.3.1` 컨트롤러 이미지는 이제 더 이상 사용되지 않으며 GitLab chart 9.0에서 제거될 예정입니다.

언급된 chart 버전으로 업그레이드할 때 기본적으로 `v1.11.2`이 설정됩니다. `nginx-ingress.rbac.create`을(를) `false`(으)로 설정하는 경우 chart는 자동으로 `v1.3.1`로 폴백합니다 (Geo `nginx-ingress-geo.rbac.create`도 동일하게 적용됨). 이는 `v1.11.2`이(가) 새로운 RBAC 규칙을 필요로 하기 때문이며, 이를 [NGINX chart](../charts/nginx/_index.md)에 추가했습니다.

자신의 NGINX RBAC 규칙을 관리 중이고 GitLab 18.0 (Helm chart 9.0)에서 강제되기 전에 새로운 `v1.11.2`을(를) 사용하려면:

1. 새로운 RBAC 규칙을 클러스터에 적용합니다 ([예제](https://gitlab.com/gitlab-org/charts/gitlab/-/merge_requests/3901/diffs?commit_id=93a3cbdb5ad83db95e12fa6c2145df0800493d8b)):

   ```yaml
   - apiGroups:
      - discovery.k8s.io
    resources:
      - endpointslices
    verbs:
      - list
      - watch
      - get
   ```

1. 컨트롤러 이미지 `v1.11.2`을(를) 다음과 같이 활성화합니다:

   ```yaml
   nginx-ingress:
     rbac:
       create: false
     controller:
       image:
         disableFallback: true
   ```

### 러너 워크플로우 변경 사항 {#runner-workflow-changes}

기존 러너 등록 워크플로우는 이제 기본적으로 비활성화되어 있습니다. [새로운 등록 워크플로우로 마이그레이션](https://docs.gitlab.com/tutorials/automate_runner_creation/) 하거나 [기존 워크플로우를 다시 활성화](https://docs.gitlab.com/administration/settings/continuous_integration/#control-runner-registration)해야 합니다.

마이그레이션 지침은 [러너 서브차트 설명서](../charts/gitlab/gitlab-runner/_index.md#requirements)를 참조하세요.
