GitLab의 `18.0` 릴리스에서 GitLab Helm 차트의 버전 `9.0`을 릴리스했습니다.

## 주요 변경 사항 요약 {#summary-of-major-changes}

- PostgreSQL 14 및 15에 대한 지원이 제거되었습니다. 업그레이드하기 전에 PostgreSQL 16을 실행 중인지 확인하세요.
- 번들된 Prometheus 차트가 15.3에서 27.11로 업데이트되었습니다.
- Prometheus 차트 업그레이드와 함께 Prometheus 버전이 2.38에서 3.0으로 업데이트되었습니다.

## 8.x에서의 업그레이드 경로 {#upgrade-path-from-8x}

### 9.4.0으로 업그레이드 {#upgrade-to-940}

#### PostgreSQL {#postgresql}

데이터베이스 진단 관련 작업에 사용할 새로운 확장 `amcheck`을 추가하고 있습니다.

기존 GitLab 인스턴스를 업그레이드하는 경우 PostgreSQL 데이터베이스에서 이 확장을 수동으로 만들어야 합니다. `amcheck` 확장을 수동으로 설치하려면 [설명서](https://docs.gitlab.com/install/postgresql_extensions/#installing-postgresql-extensions-manually)를 따르세요.

### 9.3.0으로 업그레이드 {#upgrade-to-930}

#### Cert-manager 업그레이드 {#cert-manager-upgrade}

cert-manager 하위 차트가 1.12.x에서 최신 릴리스로 업그레이드되고 있습니다. 이러한 최신 cert-manager 릴리스는 [Helm 스키마 검증](https://helm.sh/docs/topics/charts/#schema-files)을 구현하며, 이는 차트 값의 구조를 검증합니다.

현재 `certmanager.install` 값을 설정하고 있다면 `installCertmanager`로 마이그레이션하세요. 버전 9.0 이상에서 이 새로운 매개변수를 사용할 수 있지만, 기존 매개변수를 계속 사용하면 버전 9.3으로 업그레이드할 때 업그레이드 확인이 실패합니다.

번들된 cert-manager를 사용하는 경우 추가 중요한 변경 사항에 대해 cert-manager 릴리스 노트를 검토하세요:

- [v1.12에서 업그레이드](https://cert-manager.io/docs/releases/upgrading/upgrading-1.12/)
- [v1.16에서 업그레이드](https://cert-manager.io/docs/releases/upgrading/upgrading-1.16-1.17/)

### 9.0.0으로 업그레이드 {#upgrade-to-900}

#### PostgreSQL {#postgresql-1}

GitLab 18.0 릴리스의 일부로, [PostgreSQL 14 및 15에 대한 지원이 더 이상 사용되지 않습니다](https://handbook.gitlab.com/handbook/engineering/data-engineering/database-excellence/database-frameworks/postgresql-upgrade-cadence/). 번들된 PostgreSQL 하위 차트가 PostgreSQL 16으로 기본 설정되도록 업그레이드되었습니다. 데이터베이스를 업그레이드해야 합니다.

번들된 PostgreSQL 데이터베이스를 업그레이드하는 단계는 [업그레이드 단계](../installation/database_upgrade.md)에 설명되어 있습니다.

#### Prometheus 업그레이드 {#prometheus-upgrade}

GitLab 차트에 번들된 Prometheus 하위 차트를 사용하지 않는 경우 이 섹션을 건너뛸 수 있습니다.

번들된 Prometheus 하위 차트가 15.3에서 27.11로 업데이트되었으며, 이제 Prometheus 2.x 대신 Prometheus 3을 번들로 제공합니다. 사용하는 기능이 영향을 받는 경우 [Prometheus 3 마이그레이션 가이드](https://prometheus.io/docs/prometheus/latest/migration/)를 확인하세요.

여기서는 가장 중요하다고 생각되는 정보를 강조하지만, 완전한 변경 사항 목록은 업스트림 [Prometheus 차트 업그레이드 설명서](https://github.com/prometheus-community/helm-charts/tree/3aa3bbb4815854836033f42ff7fc41ed27d2904d/charts/prometheus#upgrading-chart)를 참조하세요.

- Prometheus 차트는 Helm 및 Kubernetes 레이블링 모범 사례에 맞추기 위해 여러 (선택자) 레이블을 업데이트합니다. 업그레이드하기 전에 이전 워크로드를 삭제해야 합니다.

  ```shell
  kubectl delete deployment  -l app=prometheus,heritage=Helm,release=<release name>
  kubectl delete statefulset -l app=prometheus,heritage=Helm,release=<release name>
  kubectl delete daemonset   -l app=prometheus,heritage=Helm,release=<release name>
  ```

  Prometheus 리소스의 레이블에 따라 다른 서비스가 있는 경우 이에 따라 이를 업데이트하세요.

- 번들된 `kube-state-metrics`, `alertmanager`, 노드 내보내기 또는 `pushgateway`을 활성화한 경우 업스트림 업그레이드 변경 로그에 따라 값을 업데이트해야 합니다:
  - [16.0 변경 사항](https://github.com/prometheus-community/helm-charts/tree/main/charts/prometheus#to-160),
  - [17.0 변경 사항](https://github.com/prometheus-community/helm-charts/tree/main/charts/prometheus#to-170),
  - [18.0 변경 사항](https://github.com/prometheus-community/helm-charts/tree/main/charts/prometheus#to-180) 및
  - [19.0 변경 사항](https://github.com/prometheus-community/helm-charts/tree/main/charts/prometheus#to-190).
- `configmapReload.prometheus.extraArgs`은 더 이상 호환되지 않습니다. [20.0](https://github.com/prometheus-community/helm-charts/tree/main/charts/prometheus#to-200)로의 업그레이드에 따릅니다.

#### NGINX 컨트롤러 이미지 업그레이드에는 새로운 RBAC 규칙이 필요합니다 {#nginx-controller-image-upgrade-requires-new-rbac-rules}

[GitLab NGINX 차트](../charts/nginx/_index.md)를 사용하고 있고 자신의 NGINX RBAC 규칙을 설정한 경우, 새로운 NGINX 컨트롤러 이미지 버전에 필요한 새로운 규칙을 포함하도록 이를 업데이트해야 합니다.

[8.6 업그레이드 노트](8_0.md#upgrade-to-86x-851-843-836)에서 자세히 알아보세요.
