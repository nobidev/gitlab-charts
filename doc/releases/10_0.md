With the `19.0` release of GitLab, we have released version `10.0` of the GitLab Helm chart.

This document highlights the changes with the highest impact. For a comprehensive overview, see:

- [GitLab 19.0 deprecations](https://docs.gitlab.com/update/deprecations/#gitlab-190)
- [A guide to the breaking changes in GitLab 19.0](https://about.gitlab.com/blog/a-guide-to-the-breaking-changes-in-gitlab-19-0/)

## Summary of major changes

- [NGINX Ingress is now disabled by default and replaced by Gateway API with Envoy Gateway.](https://docs.gitlab.com/update/deprecations/#support-for-nginx-ingress)
- [The bundled PostgreSQL, Redis, and MinIO have been removed from the GitLab chart.](https://docs.gitlab.com/update/deprecations/#support-for-bundled-postgresql-redis-and-minio-in-gitlab-helm-chart)
- [Support for PostgreSQL 16 has been removed. Make sure you are running PostgreSQL 17 before upgrading.](https://docs.gitlab.com/update/deprecations/#support-for-postgresql-16)
- [Resource Owner Password Credentials (ROPC) OAuth grant removed.](https://docs.gitlab.com/update/deprecations/#resource-owner-password-credentials-grant-is-deprecated)

For mitigation steps and full details, follow the linked deprecation notices.

## Upgrade to 10.3.0

### Envoy Gateway upgrade requires new Gateway API CRDs

The bundled Envoy Gateway chart is upgraded from 1.8.3 to 1.9.0. Envoy Gateway 1.9 reconciles
`TCPRoute` only from `gateway.networking.k8s.io/v1`, and Envoy Gateway 1.8 bundled Gateway API 1.5
CRDs, which serve `TCPRoute` as `v1alpha2` only. Helm does not upgrade CRDs, so upgrade the Gateway
API CRDs before you upgrade GitLab. For the upgrade command and the fallback for implementations
that do not serve `v1` yet, see the
[SSH route documentation](../advanced/gateway-api/_index.md#ssh-route).
